# Downloads整理スキル（公開用テンプレート）

> **Note**: これはGitHub公開用にサニタイズしたテンプレートです。学校名・学籍情報・
> 実際のディレクトリ構成は含まれていません。自分の環境で使う場合は、下記の
> `<...>` プレースホルダーと「振り分けルール」を自分の実態に合わせて書き換えてください。
> 実運用版（実際の科目名・パス入り）は `~/.claude/skills/` 配下にローカルのみで保持し、
> このリポジトリにはコミットしません。

`<Downloads>`（例: `~/Downloads`）の中身を、`<資料格納先ルート>`（例: `~/Documents/<学校名>/`）の
整理体系へ振り分ける。
**最重要ルール: 何をどこへ移動したか、必ず全ファイル分を明記して報告する。**

## 手順

1. **一覧化**: `ls -la` で Downloads の中身を全て把握する。
2. **格納先構成の確認**: 記憶や過去のメモを参照しつつ、`<資料格納先ルート>` 配下の
   学年・学期・科目フォルダ・週フォルダの**現状を必ず実地確認**する（記憶は古い場合がある）。
   在籍学年・学期は都度確認する。
3. **各ファイルの帰属判定**: 下記「振り分けルール」でファイル名・内容から格納先を決める。
   PDFは `pdftotext` で内容を確認して裏取りする。
4. **重複・衝突チェック（重要）**: 格納先に同名/類似名ファイルがある場合、`sha256sum` で
   **ハッシュ比較**する。
   - 完全一致 → 格納先を正としDownload側を削除。
   - 内容が違う（下書き/旧版など）→ 格納先の既存を `_旧版(日付)` 等にリネームして退避してから
     新版を配置し、データを失わない。
   - 名前が衝突しない別ファイルなら、上書きせずそのまま併置。
5. **移動**: `mv -n`（no-clobber）で移動。新規フォルダが要る場合は `mkdir -p`。
6. **検証**: 移動元が空になったか・移動先に入ったかを `ls` で確認。
7. **報告**: 全ファイルの移動先を表形式で明記。据え置いたもの（システムファイル等）も
   理由付きで明記。

## 振り分けルール（パターン例 — 自分の科目構成に置き換える）

- **グループ課題の科目コード表記や `【ﾁｰﾑ_NN】` のようなチーム番号表記** → 該当科目フォルダ
  - 章別レポート（`N章_…docx` 等）→ 章別レポートが集まる週フォルダに集約。
  - 最終発表スライド → 最終回の週フォルダ。
- **`<学籍番号>_<クラス>_◯◯.pdf` 形式（確認テスト・自己点検 等）、および座席表** →
  該当科目の該当週。※分類が曖昧な書類は本人の希望ルールがあればそれに従う。
- **外部演習サービスの成績・証明書類** → 関連科目の該当週（ダウンロード日付に一番近い週）。
- **翌学期関連の書類**（オリエン案内 等）→ 翌学期側のフォルダ。無ければ当学期と同構成で新設。
- **使用教科書一覧・科目メモ等の一般学業書類** → オリエンテーション用フォルダ。
- **アルバイト応募関連**（履歴書・送付状）→ 個人用フォルダの「アルバイト」系サブフォルダ。
- **個人制作物** → 個人用フォルダの制作物カテゴリ別サブフォルダ（言語・種別ごと）。
- **参加イベント記録**（ハッカソン・展示会等） → 個人用フォルダのイベント記録サブフォルダ。
- **認証・バックアップコード類** → 個人用フォルダの機密サブフォルダ（機密性高。取り扱い注意）。
- **住居関連書類** → 個人用フォルダの住居カテゴリ（年度別）。

## 判断に迷う・機微なファイルの扱い

- 学業と無関係な個人的・機微な内容（トラブル・謝罪文など）で格納先が曖昧な場合は、
  憶測で決めず `AskUserQuestion` で確認する。
- 科目が特定できない学業書類は、まず内容（`pdftotext`）で科目名の手掛かりを探す。
  それでも不明なら確認する。

## 据え置くもの（移動・削除しない）

- `desktop.ini` … Windowsのフォルダ設定用システムファイル。
- `.tmp.driveupload` … クラウドストレージ同期用の一時フォルダ（同期アプリ管理下）。
