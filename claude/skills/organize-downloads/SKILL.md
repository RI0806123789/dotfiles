# Downloads整理スキル

`~\Downloads` の中身を、`~\Documents\KIT\` の整理体系へ振り分ける（一部は `~\Documents\GitHub\` 配下へ）。
**最重要ルール: 何をどこへ移動したか、必ず全ファイル分を明記して報告する。**
※ 学籍番号・クラス番号は本人の学生証等に合わせて読み替える（下記の `<学籍番号>` `<クラス番号>` 参照）。

## 手順

1. **一覧化**: `ls -la` で Downloads の中身を全て把握する。
2. **格納先構成の確認**: 下記「KITディレクトリ構成」とメモリ `kit_directory_structure` を参照しつつ、**在籍学期の科目フォルダ・週フォルダは必ず実地確認**する（メモリ・本スキルは古い場合がある）。
   - 在籍学期 = `01_Grade\` 配下で、科目フォルダ（`01_`〜）が存在する最新の学期フォルダ。**2026-09-27時点は2年2学期 = `02_2nd\02_2ndSemester`**。
   - 終了済みの学期は構成が確定しているので、毎回スキャンし直す必要はない（同名ファイルの照合が必要なときだけ見る）。
3. **各ファイルの帰属判定**: 下記「振り分けルール」でファイル名・内容から格納先を決める。PDFは `pdftotext` で内容を確認して裏取りする（画像PDFや、PowerPoint/LaTeX製で日本語が抜け落ちる場合は `Read` で目視）。
4. **重複・衝突チェック（重要）**: 格納先に同名/類似名ファイルがある場合、`sha256sum` で**ハッシュ比較**する（Windows版の出力はファイル名の先頭に `*` が付くので、スクリプトで照合するときは除去する）。
   - 完全一致 → 格納先を正としDownload側を削除。
   - 内容が違う（下書き/旧版など）→ 格納先の既存を `_旧版(日付)` 等にリネームして退避してから新版を配置し、データを失わない。
   - 名前が衝突しない別ファイルなら、上書きせずそのまま併置。
5. **移動**: `mv -n`（no-clobber）で移動。新規フォルダが要る場合は `mkdir -p`。
6. **検証**: 移動元が空になったか・移動先に入ったかを `ls` で確認。
7. **報告**: 全ファイルの移動先を表形式で明記。据え置いたもの（システムファイル等）も理由付きで明記。
8. **記録**: 新学期の科目で初めて判明したファイル名規則や、本人から受けた修正指示は、メモリ `kit_directory_structure` / `feedback_downloads_organizing` に追記する。

## 判断に迷う・機微なファイルの扱い

- 学業と無関係な個人的・機微な内容（トラブル・謝罪文など）で格納先が曖昧な場合は、憶測で決めず `AskUserQuestion` で確認する。過去は `03_Individual\Other` が受け皿になった実績あり。
- 科目が特定できない学業書類は、まず内容（`pdftotext`、Officeファイルはシート名・スライド見出し）で科目名の手掛かりを探す。複数科目にまたがる、またはそれでも不明なら確認する。
- 学業と無関係な私的購入コンテンツ（音声作品等の大容量ファイル）は質問せず Downloads に据え置き、報告に「対象外」と明記する。
- Claude Code が生成した個人的な分析レポート（`output.md` 等）: 2026-09-08 はDownloadsに据え置く指定だったが、その後本人が `03_Individual\Other` へ移していた（2026-09-27確認）。同種が来たら `Other` を提案して確認する。

## 据え置く・削除するもの

- **据え置き**: `desktop.ini`（Windowsのフォルダ設定用システムファイル）、`.tmp.driveupload`（Googleドライブ同期の一時フォルダ）。
- **削除可**: 学業と無関係で、使い捨て・テスト目的と明らかなファイル（Appleの `event.ics` 招待、動作確認用の `memo.md` 等）。削除したものも報告に明記する。
